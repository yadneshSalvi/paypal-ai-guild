# Local provider marketplace qualification

The public launcher runs the existing production Next HTTP and compiled-client DOM suite from a clean Guild checkout. It derives the project and guard paths from its own location and uses installed project dependencies. It does not depend on a private sibling checkout, configuration wrapper or DOM harness.

Run it with Python 3.10 or later, Node 22.x, `git`, `ps` and `lsof` on macOS or Linux. Install the lockfile dependencies first with `npm ci` using your authorized package-registry access. Dependency installation is separate networked setup; it is not part of the guarded qualification.

Use a clean isolated checkout with no `.next` directory and no environment files. The public `.env.example` template is allowed, but it is never loaded. Build and typecheck receive no database or auth credentials. All children receive a minimal environment with model, media and payment keys empty.

## Explicit inputs

Every invocation requires:

- `--evidence-dir`: a private 0700 directory owned by the caller, **outside the checkout**. The first `freeze` requires it empty. Keep it on the same filesystem as the checkout if you need to retire an owned build by rename.
- `--origin`: an explicitly owned `http://127.0.0.1:port` origin. The example below uses 4590. The launcher refuses occupied ports and never stops a collision.
- `--protected-root` on the first freeze: a workspace directory containing the original checkouts and private evidence that children must not read. It can be repeated. The exact roots are retained; later invocations can omit them or repeat the same values.
- Optionally `--node`: an explicit Node 22 executable. Otherwise it resolves Node from PATH. Its path, version and binary hash are pinned for this fixture.

For `prepare`, `start`, `test` and `check`, also provide `--database-url-file`. This must be a private 0600 file outside the checkout, containing either one PostgreSQL URL or JSON with a `databaseUrl` string. Other JSON members are ignored; auth/session secrets are freshly generated by the launcher and retained privately.

The supplied database must belong to your disposable local PG instance on 55568. Use an absolute Unix socket directory or an exact local IP (`127.0.0.1` or `::1`), explicit database/user and `sslmode=disable`. For example, replace the placeholders in this private JSON file:

```json
{"databaseUrl":"postgresql://TEST_ROLE@127.0.0.1:55568/TEST_DATABASE?sslmode=disable"}
```

For a Unix socket, the URL can instead use `?host=ABSOLUTE_SOCKET_DIRECTORY&port=55568&sslmode=disable`; percent-encode URL values as needed. Do not put real passwords or URLs in shell arguments, public files, screenshots or reports. Pass the private file path.

Provision that test instance/database separately. The launcher never starts or stops PostgreSQL. Its read-only preflight requires the actual server port to be 55568 and rejects roles with superuser, database-creation, role-creation, replication or bypass-RLS flags. A disposable database owner with LOGIN and database CONNECT/CREATE privileges is sufficient for the fresh schema and migrations. On a separately owned test instance, an administrator can create such a role/database with:

```sql
CREATE ROLE guild_market_qual LOGIN
  NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS;
CREATE DATABASE guild_market_qual OWNER guild_market_qual;
```

Configure local authentication independently. Never apply these setup commands to an existing production instance. The URL cannot supply an existing schema/search path, service file or arbitrary connection options. The launcher generates a new `guild_market_next_worker_<random>` schema and pins the original database endpoint/URL hash before preparation.

## Build, prepare and qualify

From the Guild checkout, choose your own private paths. These commands use shell variables for convenience; they contain no credentials:

```sh
umask 077
MARKET_CHECK_EVIDENCE="$(mktemp -d "${TMPDIR:-/tmp}/guild-market-next.XXXXXXXX")"
MARKET_CHECK_ORIGIN="http://127.0.0.1:4590"
MARKET_CHECK_WORKSPACE="/absolute/workspace/containing/original/checkouts"
MARKET_CHECK_DATABASE_FILE="/absolute/private/test-database.json"

python3 scripts/check-provider-market-next.py freeze \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN" \
  --protected-root "$MARKET_CHECK_WORKSPACE"

python3 scripts/check-provider-market-next.py build \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN"

python3 scripts/check-provider-market-next.py refreeze \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN"

python3 scripts/check-provider-market-next.py typecheck \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN"

python3 scripts/check-provider-market-next.py prepare \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN" \
  --database-url-file "$MARKET_CHECK_DATABASE_FILE"

python3 scripts/check-provider-market-next.py start \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN" \
  --database-url-file "$MARKET_CHECK_DATABASE_FILE"

python3 scripts/check-provider-market-next.py test \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN" \
  --database-url-file "$MARKET_CHECK_DATABASE_FILE"
```

`refreeze` after the build records generated `next-env.d.ts` when present. Every freeze includes source, scripts, tests and the Git-visible project inputs. Before/after operation manifests are immutable files. A refreeze cannot make an old compiled build current: `start` compares current source against the original successful build's after-manifest, build ID and compiled-file hashes. Only `next-env.d.ts` may change as an expected generated build input; other build-time source drift fails qualification.

The build must be created here from an absent `.next` directory. Copied or unowned builds are refused. `prepare` calls the existing fixture preparation entrypoint once, applies migrations only inside its fresh generated schema, and retains the exact buyer/provider sessions, identities and absolute expiries. It refuses an existing schema, fixture export or prepare claim. Build/refreeze/restart never regenerate those identities or extend deadlines. Read-only database preflights compare original session/tenant roles, bindings and expiries before runtime/test operations.

`test` runs `tests/provider-market-next-http.test.ts`, which invokes the existing sixteen-check production HTTP/DOM suite. `check` runs its script entrypoint directly as an alternative. Choose **one**: both share a single qualification claim because this suite changes controlled negotiation/approval/task state. A second attempt is refused even after failure; it cannot silently generate replacement commands, links or fixtures.

## Modes and retained outcomes

| Mode | Behavior |
| --- | --- |
| `freeze` | Initialize a new empty private evidence directory, schema/auth identities and source manifest; require an absent application port/build. |
| `refreeze` | Add a new immutable source manifest, retaining the same fixture/auth/schema values. Requires no runtime. |
| `build` | Run the installed Next production build with no database/auth/provider credentials; retain its log, source manifests and owned build record. |
| `typecheck` | Run TypeScript with `--noEmit --incremental false`, no database/auth/provider credentials, and source manifests. A clean build may be needed first for generated Next types. |
| `prepare` | Refuse existing fixture/schema, then create exactly one controlled fixture using the explicit restricted database. |
| `start` | Start only the recorded build on the exact 127.0.0.1 origin; retain PID/start/cwd/executable, guard nonce/hash, build and log records. |
| `test` / `check` | Verify original runtime, source/build, database and fixture deadlines, then run one real Next qualification attempt. |
| `status` | Inspect the retained process/listener records without renewing data or modifying a runtime. |
| `stop-owned` | Explicitly verify the original PID/start/cwd/executable/listener/build/guard before sending that PID one SIGTERM. No process-group kill, SIGKILL or collision cleanup. |
| `archive-build` | With no runtime, verify and rename only this fixture's exact known build into private retained evidence, allowing an explicit clean rebuild. No cross-filesystem copy fallback. |

To inspect and explicitly stop the owned runtime:

```sh
python3 scripts/check-provider-market-next.py status \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN"
python3 scripts/check-provider-market-next.py stop-owned \
  --evidence-dir "$MARKET_CHECK_EVIDENCE" --origin "$MARKET_CHECK_ORIGIN"
```

Stop before editing/rebuilding. For an intentional source repair, preserve failed reports, explicitly stop the verified runtime, `archive-build`, review the source, `refreeze`, then `build` and `refreeze` again. The original schema/auth/fixture export and deadlines remain fixed. The mutating test claim is never cleared to make a failed fixture look fresh. Once its deadline expires, retain it as evidence; a separately authorized new qualification needs a new evidence directory and schema.

Failures, child PIDs, logs, source manifests and unknown outcomes remain private. There is no automatic retry, reseed, link renewal, task replay or database deletion. An interrupted operation with no observed child result blocks later mutating operations. Inspect its exact retained PID/log before proceeding; do not erase a claim or overwrite a record. If a runtime has already exited and the port is empty, explicit `stop-owned` records that observation without sending a signal. A changed/reused PID or another listener is always refused.

## Guard and evidence limits

The preload denies dotenv loading and standard Node file reads of protected workspace paths outside this checkout and its explicit evidence directory, including symlink escapes. It denies fetch/HTTP/TCP connections beyond the exact owned HTTP endpoint and the caller-bound PG socket or local IP/port. Build/typecheck have no database endpoint at all. Queries, headers, bodies, cookies, tokens and link challenges are omitted from guard traces. Source/runtime records and fixture exports are private; never publish the evidence directory or its native-entry packet.

This JavaScript preload is a qualification guard, not an operating-system sandbox against hostile native code. Run only reviewed source/dependencies in the isolated checkout. The launcher does not claim to restrict arbitrary commands outside its children or independently prove external endpoint ownership.

The suite exercises actual Next production HTTP routes and the JavaScript served by that build through DOM emulation. DOM emulation does not establish native browser layout, keyboard, mobile, screen-reader or human approval acceptance. Native review is a separate owner-controlled gate. Before native actions, retain a read-only full-row baseline; compare it afterward and report any missing before-data honestly.

Seven addressed services, fixture owner policies/approvals and controlled job/artifact transitions are Guild-controlled test evidence. They do not establish independent outside businesses, actual provider/model/media production, human artifact acceptance, captured payments or payouts. Do not visit workspace/Studio polling routes while a newly controlled job is queued: those existing routes can schedule workers. The marketplace task/read routes do not execute workers.

A passing run must be supported by its retained Next report, Node test result, source/build records, guard traces and fixed fixture deadlines. Actual model/provider/financial operations, outside-provider onboarding, production hosting and full protocol conformance remain separate qualifications.
